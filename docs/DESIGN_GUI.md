# DESIGN_GUI.md — NVR 导出 GUI 单体程序(Windows .exe)设计

> 目标:在现有 CLI 协议引擎 `scripts/nvr_dump.py` 之上,盖一层 GUI,打包成 Windows 单体 .exe。
> 原则:**协议层零重写**——它已经用实测踩坑换来,重写即违约(见 AGENTS.md 铁律一)。

## 1. 交付物

- Windows 单体 .exe(双击即用,无需装 Python)
- 源代码 + 一键构建脚本(在 Windows 上跑一次即出 exe)
- 保留现有 CLI 工具(两者共用同一协议引擎)

## 2. 关键现实约束(重要)

当前这台机器是 **Linux**(`/data/project`)。PyInstaller 不能交叉编译,所以:
- **我负责交付**:完整 GUI 源码 + PyInstaller 打包配置 + Windows 一键构建脚本(`build_exe.bat`)。
- **你在 Windows 上执行**:装 Python → 跑 `build_exe.bat` → 得到 `NVR导出.exe`。
- 这一步我会在文档里写清楚,确保你零障碍完成。

## 3. 技术选型(越小越好 → 全走标准库/最小依赖)

| 层 | 选型 | 理由 |
|---|---|---|
| GUI | **tkinter + ttk**(Python 标准库) | 零 GUI 依赖、打包最小;功能足够(表格、多选、进度、日志文本框) |
| 网络/协议 | **requests.Session + HTTPDigestAuth**(复用现有) | 与 CLI 完全一致,长连接复用/digest 一次握手 |
| 打包 | **PyInstaller `--onefile --windowed`** | 单体 exe、无控制台黑窗 |
| 线程 | threading + queue → tkinter 主循环 | 导出不卡界面,进度实时刷新 |

**为什么不选 PyQt/PySide**:打包后 exe 50MB+,且引入大依赖,违背"越小越好"。tkinter 是"功能简单明确"的匹配选择。

> 预计 exe 体积 **15~20 MB**(py3.11 + tkinter + requests 的单体打包),已是最小可行。

## 4. 软件架构(标准 PC 三层)

\`\`\`
+-----------------------------------------------------------+
|  GUI 应用层 (nvr_gui.py)                                    |
|  界面:连接配置 / 通道选择 / 导出参数 / 进度日志               |
|  控制器:后台导出线程 + queue 推送进度到主循环                 |
+-----------------------------------------------------------+
|  协议引擎层 (nvr_dump.py,复用/零改)                          |
|  get_channel_titles / find_segments / download_segment       |
|  safe_name / out_name / parse_channel_spec                  |
+-----------------------------------------------------------+
|  打包层 (build_exe.bat + .spec)                              |
|  PyInstaller --onefile --windowed → NVR导出.exe             |
+-----------------------------------------------------------+
\`\`\`

- GUI 通过 `import nvr_dump` 复用协议引擎,**不改动 nvr_dump.py 一行**(它的 `__main__` 不影响 import)。
- GUI 自写"编排循环"(枚举→预检→下载→进度),复用底层原子函数,这样进度能实时推给界面。

## 5. 界面布局(单窗口,自上而下)

| 分区 | 控件 | 说明 |
|---|---|---|
| ① 连接配置 | NVR IP 列表(可增删行,默认 4 台)、用户名、密码 | "检测/连接" 按钮:拉通道表 |
| ② 通道选择 | 表格(通道号 + 通道名,checkbox 多选) | 来自实时 ChannelTitle,便于"每 NVR 各选各的" |
| ③ 导出参数 | 时间窗(起/止,可加多个窗口)、保存目录(浏览)、命名方式(按教室/完整名/平铺)、每 NVR 并发 | 默认并发 4(不可调大,防打崩 NVR) |
| ④ 操作区 | [预检] [开始导出] [停止] | 预检→确认弹窗→开始 |
| ⑤ 状态区 | 进度条、当前/总数、已下 GB、平均 MB/s、日志文本框 | 实时刷新 |

## 6. 功能数据流

`\`\`
检测连接 → 枚举通道(显示在②)
   ↓
选择通道 + 设时间窗 + 选保存目录
   ↓
[预检] = dry-run 枚举段数 + 总GB + 按基准吞吐估预计时间
   → 弹窗:可导出 ✓ / 段数 / 大小 / 预计时长 / 目标盘剩余空间检查
   → 用户点"确定"
   ↓
[开始导出] → 后台线程逐段下载(断点续传、magic 校验、失败重试)
   → 进度条 + 日志实时刷新
   ↓
全部完成 → 在导出根目录写 `说明.txt` → 汇总 OK/FAIL/清单
\`\`\`

## 7. 断点续传与容错(完全复用现有机制)

- 重跑跳过已存在文件;临时文件 `.part<tid>`,验 DHII magic + 长度(±4KB)后 rename。
- 每段失败自动重试 2 次(带退避)。
- subcode 流排除、同名撞车处理——沿用现有逻辑。
- **新增**:下载中断后重开软件,勾选同样通道/时间窗,自动跳过已完成部分。

## 8. `说明.txt`(自动写入导出根目录)

固定模板,内容示例:
\`\`\`
================ NVR 录像播放说明 ================
一、播放器
  本目录录像为大华 NVR 原始 .dav 格式,需用大华专用播放器播放:
  - 推荐:大华 SmartPlayer(网络可搜 "大华 SmartPlayer 下载")
  - 或大华乐橙/录像机配套客户端
  下载来源:大华官网支持中心,或联系管理员拷贝安装包。

二、如何打开
  1) 安装 SmartPlayer
  2) 打开软件 → 文件/打开 → 选择本目录下的 .dav 文件
  3) 即可播放对应时间段的原始录像

三、直接改名观看(可选)
  部分播放器/工具可直接识别:把 .dav 改为 .mp4 试播
  (多数情况无声音/可能花屏,仅应急,推荐用官方播放器)

四、文件命名说明
  文件名格式: <通道名>_<开始时间>_<结束时间>_<编号>.dav
  示例: 九教室东_2026-07-12_08-30-00_000001.dav
=================================================
\`\`\`

## 9. 目录/文件命名(沿用 CLI 规则)

- 目录:按教室(合并多路)→ 完整摄像头名 → 平铺(三选一,默认按教室)。
- 文件:`out_name()`(`通道名_时间窗_编号.dav`),特殊字符已 sanitize。

## 10. 打包流程(Windows 侧)

\`\`\`
1. 装 Python 3.11+(勾选 Add to PATH)
2. 打开 cmd → `pip install pyinstaller requests`
3. 进入项目 `app/` 目录 → 运行 `build_exe.bat`
4. 产物在 `app/dist/NVR导出.exe`
\`\`\`
