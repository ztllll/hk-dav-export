# LESSONS.md — 协议细节与踩坑实录

> 结论都来自对 4 台大华 NVR(固件 5.001 build 2026-03-31)的实测。改脚本前先读这里。

## 一、大华 CGI 协议(勿凭记忆改)

1. **枚举必须两步**:`findFile` 只返回 `OK`,真正的录像列表在 `findNextFile`。只调 findFile 永远"0 录像"。每批 `count=100`,`found<100` 时结束循环。
2. **查询条件用 dot-form 独立参数**:
   `condition.Channel=N&condition.StartTime=2026-07-12%2009:00:00&condition.EndTime=...`
   URL-encoded 单值形式(`condition=Channel%3D...`)在 v5 固件 100% 返 400。
3. **下载接口**:`GET /cgi-bin/RPC_Loadfile<FilePath 按段 urlencode,保留 />`。
   - 不支持 `Range` 断点续传,断了只能整段重下
   - FilePath 末尾可能带 `\r`,encode 前必须去掉
4. **.dav 文件头 magic = `44484949`(ASCII "DHII")**,不是 "DAHUA"。每段下载后必须验头,失败丢弃重试,不能直接 mv 成 .dav。
5. **子码流陷阱**:部分通道同一时段会同时返回 `VideoStream=Main` 和 `Extra1` 两条记录,FilePath 目录不同(如 `/0/` vs `/128/`)但**文件名完全相同**→ 输出撞车、且 Extra1 是低清流。必须过滤只留 `Main`。
6. 通道名实时拉 `configManager.cgi?action=getConfig&name=ChannelTitle`,不要信本地缓存映射(`data/channel_map.tsv` 仅参考)。
7. **findFile 偶发返回空结果**:同参数稍后重查即出(2026-09-05 实测,50.2 某连续录像通道在预检中被误报 0 段,复查实有 45 段)。对"0 段"结论必须二次复检,勿直接判无录像——GUI 预检已内置复检。
8. **通道号错位(2026-09-07 四台 NVR 实测一致,致命级)**:`table.ChannelTitle[N]` 是 **0 基槽位**,而 mediaFileFind 的 `condition.Channel`、snapshot 的 `channel`、存储目录号(FilePath 中 `/N/`)都是 **1 基 = 槽位号+1**。按标题下标直查会整体错位一位(如查槽位 0 一教室东 → 媒体 ch0 不存在 → 快照 400/枚举 0 段,实际录像在媒体 ch1/存储 /0/)。引擎 `find_segments` 已统一 +1 映射,调用方一律传槽位号,勿重复加。**2026-07-12 的导出因此存在内容整体前移一个机位的风险(文件名为 N 槽位、内容为 N-1 槽位),复用旧文件前需核对画面水印与文件名**。
9. **段文件头部残留旧帧(2026-10-24 实测,50.3)**:RPC_Loadfile 返回的段在 DHII 头之后、正片帧(约 2MB 偏移)之前,可能残留**数月前的 DHAV 帧**(磁盘预分配块复用,如 9/23 14:00 段开头是 4/22 20:41 的 ~1.7MB)。索引时间、文件名都正确,但播放器从首帧起播 → 画面时间错成别的时段(老板报“选下午 2 点,播出来是晚上 8 点”)。50.1/.2/.4 该区域干净。引擎 `scrub_stale_head` 在下载落盘前把正片首帧(帧头 +16 的打包时间落在段 StartTime~EndTime ±5 分钟内)之前的 DHAV 清零:**不截断**,长度校验不变、幂等。此前导出的 50.3 文件同样受影响,需重导或用新版重跑(已存在的文件会被跳过,要先删)。

## 二、性能结论(为什么老脚本慢)

| 做法 | 结果 |
|---|---|
| 每段新起 curl 进程 + Digest 重握手(老脚本) | 慢 + 47% 失败率 |
| requests.Session 长连接复用 | 单连接 15-50 MB/s,失败率 0 |
| 每 NVR 并发 4 | 最优;>4 撞 NVR 单盘 IO,吞吐反降 |
| 4 台 NVR 同时拉 | 聚合 50 MB/s(本机 SSD)/ 25 MB/s(NTFS 移动硬盘) |

- NVR 本身不是瓶颈,瓶颈依次是:目标盘写速 > 网络 > NVR。
- NVR 偶发 connect timeout(疑似轻度反爬/繁忙),**重试 2-3 次带退避**即可全部恢复,不需要更复杂的对策。

## 三、运维踩坑

1. **`/tmp` 是 tmpfs(约 7.6G)**,大文件测试/下载禁止写 `/tmp`,会 `Disk quota exceeded`。用 `/data` 或直接写目标盘。
2. **会话后台 `sleep N` 定时任务会被系统回收**(killed)。长任务监控用会话 cron(CronCreate);真正的长任务本体用 `setsid nohup ... < /dev/null &` 完全脱离会话。
3. **并发写同一 .part 文件会互相覆盖**:临时文件名要带线程 id(脚本已处理:`.part<tid>`)。
4. cifs 共享(`//10.10.55.2/D`)重启后不会自动重挂,用前先 `mount | grep share-d` 检查。
5. USB 双盘对拷时如有其他进程同时读写任一盘,速度从 ~30 MB/s 掉到 ~8 MB/s;避免叠加 IO。
6. NTFS 移动硬盘用内核 `ntfs3` 挂载(不是 ntfs-3g/fuse),性能足够。

## 四、业务经验(选路)

- 教室摄像头命名规律:`<教室名>东/西/中(前后/东西)`。"每教室 2 路"默认选 **东+西**。
- **必须逐路预飞核实有无录像**再定选路:2026-07-12 发现九教室东、十四教室东、十七教室东整天无录像(设备问题),用同教室"中"位替补。不预飞就会交付缺路。
- 一天两场考试(如 08:30-11:00 + 13:30-16:00)用两个 `--window`,一次跑完,不要分两次任务。
